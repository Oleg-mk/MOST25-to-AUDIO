# Ноутбук: запис у машині й розбір удома

| Файл | Що це |
|---|---|
| `record.bat`, `record.command` | запуск запису: Windows і macOS |
| `decode.bat`, `decode.command` | запуск розбору вдома |
| `console_log.py` | записувач консолі хоста (ESP32), з позначками й тривогами |
| `trace_decode.py` | розбір запису у файли, які можна читати |
| `console_format.py`, `capture_analyse.py` | розбір рядків консолі й дампу лінії; їх використовують обидві програми |
| `requirements.txt` | pyserial, який `record` ставить сам |

Програми — копії з `tools/` репозиторію. Записи лягають у `logs/` поруч із цими файлами.

## Python

- **Windows 10/11:** Python 3 з python.org (3.13 або новіший), при встановленні поставити «Add
  python.exe to PATH».
- **macOS (і Apple Silicon):** Python 3 з python.org або `brew install python`.

Перший запуск `record` сам створює `.venv` з pyserial. Інтернет потрібен один раз.

## Підключення

Ноутбук іде в USB модуля M2 (ESP32-DevKitC), не модуля FPGA.

### Драйвер моста

На платі ESP32 стоїть міст CP2102N або CH9102. `record` знаходить його сам за USB ID, назва
порту не важлива. Якщо порт не з'являється, потрібен драйвер:
- **Windows** зазвичай ставить драйвер сам. Якщо в Диспетчері пристроїв немає COM-порту,
  поставити Silicon Labs CP210x VCP (silabs.com) або драйвер WCH для CH9102 (wch-ic.com).
- **macOS:**
  - для CP2102N, якщо `ls /dev/cu.*` не показує `cu.usbserial-…`, поставити Silicon Labs CP210x VCP
    (є збірка для Apple Silicon) і дозволити його в «Конфіденційність і безпека»;
  - CH9102 macOS 13 і новіші підхоплюють своїм драйвером.
- **Apple Silicon:** на питання про новий аксесуар відповісти «Дозволити».

`record` відкриває порт, не чіпаючи DTR і RTS. На DevKitC ними скидають ESP32, тож запис хоста не
перезапускає. Деякі драйвери все ж смикають їх при відкритті порту: тоді ESP32 стартує заново, і
запис це покаже.

## Запис

Windows: подвійне клацання по `record.bat`.

macOS: подвійне клацання по `record.command`. Якщо macOS його не пускає, вперше: права кнопка,
«Відкрити».

Якщо поруч є `record_args.txt`, його рядок додається до кожного запуску. Наприклад,
`--port COM7`, якщо мостів кілька, або `--auto-mark 60` для позначки щохвилини.

### Рядок стану

`mark` — номер останньої позначки. Далі:
- `lost: bad … fpga … seg … trace …` — втрати на нашому боці від старту ESP32. Має лишатися 0.
- `gaps`, `parity` — розриви в блоках керування і блоки, відкинуті за парністю.
- `tel` — скільки телеграм прийшло.
- `starts` — скільки разів стартував ESP32.
- `W/E` — попередження й помилки хоста.
- `dumps` — дампи лінії.
- У кінці останнє значення звуку (гучність, тембр), а якщо такого ще не було — остання телеграма.

На початку рядка стоять тривоги, поки вони тривають: `NO LINE FOR … s`, `PORT …`, `DISK ERROR`.

### Звуки

Високий короткий — позначка. Низькі довгі — тривога:
- порт втрачено (повторюється кожні 10 с, доки його немає);
- ESP32 стартував заново;
- зріс лічильник втрат;
- 25 с без жодного рядка;
- хост не відповів на клавішу;
- помилка диска.

Що саме сталося, видно в рядку стану.

### Клавіші

- `m` — позначка: звук і велике число на екрані. Що зробили, сказати з цим числом у диктофон
  телефона або дописати нотатку.
- `n` — нотатка до останньої позначки: пишеться в рядку стану, Enter закінчує, Esc скасовує. Запис
  тим часом не зупиняється.
- `d` — хост друкує дамп того, що захопила FPGA. Після вмикання це старт кільця.
- `c` — FPGA захоплює лінію заново, хост друкує дамп, коли буфер заповниться. Програма перепитує:
  ще не надрукований дамп старту кільця пропаде.
- `q` — вихід (перепитує).

Клавіші працюють і в українській чи російській розкладці (`ь т в с й н`), і з Caps Lock.
Підмішування (`i` на консолі хоста) з цієї програми не вмикається ніколи.

Ноутбук не засинає, поки йде запис. Але на Windows для закритої кришки треба поставити
«Закриття кришки: нічого не робити», а MacBook має лишатися відкритим.

## Що записати в машині

1. **Старт кільця.** Ноутбук під'єднати й запустити `record` до того, як машина прокинеться.
   Після пробудження натиснути `d`: дамп старту кільця потрібен для кроку 1 запуску.
2. **Шкали звуку.** Кожен регулятор (гучність, низькі, високі, баланс) провести від одного краю до
   іншого, з позначкою на кожному краї й нотаткою, що це було. Якщо в меню машини є гучність
   парктроніка або звукових сигналів, провести так само й їх.
3. **Кнопки керма.** Натиснути кнопку, одразу позначка й нотатка («наступний трек» тощо).
4. **Джерела.** Перемкнути джерела, зокрема на AUX, кожне з позначкою.

## Розбір удома

Windows: подвійне клацання по `decode.bat` розбирає найновіший запис. Можна перетягнути на нього
`.log` потрібного запису.

macOS: `decode.command`, або в Терміналі `bash decode.command logs/<запис>`.

Результат лягає в `logs/<запис>.d/`:
- `summary.txt` — частини запису, старти ESP32, лічильники й кожен їхній ріст, тиша, позначки,
  дампи, функції за частотою.
- `sound.txt` — для кожного значення звуку найменше, найбільше й кожна зміна, з позначками між
  ними. З цього визначаються шкали машини.
- `marks.txt` — телеграми від 5 с до кожної позначки до 3 с після, і в кожної видно, як часто її
  функція траплялась за весь запис. Рідкісна поруч із позначкою — це натиснута кнопка.
- `telegrams.csv` — усі телеграми.
- `functions.txt` — кожна функція з її корисними даними.
- `console.txt` — решта рядків хоста.
- `dump_N.txt` з `dump_N_analysis.txt` — кожен дамп лінії і що з нього читається: швидкість кільця,
  преамбули, парність.

Розібраний запис (`logs/<запис>.d/`) повертається в репозиторій: з нього заповнюються шкали.
